Polaris REST API

Read audit data from Polaris in your own systems, dashboards and scripts. Every request is read-only and authenticated with an API key.

Quick start

Replace https://your-polaris-host with your Polaris address and YOUR_API_KEY with a key you generated.

curl -H "x-api-key: YOUR_API_KEY" \
  "https://your-polaris-host/api/v1/engagements?page=1&page_size=25"

A 200 response with a data array means you are connected.

Get an API key

Only administrators can create keys.

  1. Open Admin > API Keys.
  2. Select Generate API Key.
  3. Enter a name (for example “Power BI reporting”), choose the scopes the system needs, and set an expiry date.
  4. Copy the key straight away. Polaris shows it once and stores only its SHA-256 hash, so a lost key cannot be recovered. Generate a new one instead.

To stop a key working, revoke it on the same page. Revoked and expired keys return 401.

Authentication

Send the key in the x-api-key header on every request. Use HTTPS only. Keys in URLs or query strings are rejected.

GET /api/v1/engagements HTTP/1.1
Host: your-polaris-host
x-api-key: YOUR_API_KEY
Accept: application/json

Scopes

A key can only read the data its scopes allow. A request outside the key’s scopes returns 403.

ScopeAllows reading
engagements:readEngagements and their status
audit-plan:readAnnual audit plans and plan periods
risks:readRisk assessments and ratings
findings:readAudit findings and recommendations
followups:readCorrective action tracking
tasks:readTasks and scheduling
resources:readResource allocation and time
reports:readReport summaries and dashboard figures

Give each system the fewest scopes it needs.

Code examples

Each example lists open engagements and prints their titles.

curl -H "x-api-key: $POLARIS_KEY" \
  "https://your-polaris-host/api/v1/engagements?status=open&page_size=100"
import os, requests

BASE = "https://your-polaris-host/api/v1"
HEADERS = {"x-api-key": os.environ["POLARIS_KEY"]}

page = 1
while True:
    r = requests.get(f"{BASE}/engagements", headers=HEADERS,
                     params={"status": "open", "page": page, "page_size": 100},
                     timeout=30)
    r.raise_for_status()
    body = r.json()
    for e in body["data"]:
        print(e["title"])
    if page * body["meta"]["page_size"] >= body["meta"]["total"]:
        break
    page += 1
const BASE = "https://your-polaris-host/api/v1";
const headers = { "x-api-key": process.env.POLARIS_KEY };

const res = await fetch(`${BASE}/engagements?status=open&page_size=100`, { headers });
if (!res.ok) throw new Error(`Polaris API error ${res.status}`);
const { data, meta } = await res.json();
data.forEach(e => console.log(e.title));
console.log(`Total: ${meta.total}`);
using System.Net.Http.Json;

var http = new HttpClient { BaseAddress = new Uri("https://your-polaris-host/api/v1/") };
http.DefaultRequestHeaders.Add("x-api-key", Environment.GetEnvironmentVariable("POLARIS_KEY"));

var result = await http.GetFromJsonAsync<JsonElement>("engagements?status=open&page_size=100");
foreach (var e in result.GetProperty("data").EnumerateArray())
    Console.WriteLine(e.GetProperty("title").GetString());

Responses

List endpoints return a data array and a meta object.

{
  "data": [
    {
      "id": "eng_1042",
      "title": "Grants disbursement review",
      "status": "open",
      "engagement_type": "Compliance",
      "lead_auditor": "N. Zwane",
      "planned_start": "2026-02-01",
      "planned_end": "2026-03-15",
      "updated_at": "2026-11-10T08:30:00Z"
    }
  ],
  "meta": { "page": 1, "page_size": 100, "total": 37 }
}

Every response includes an x-request-id header. Quote it when you contact support.

Errors

Errors return a JSON body and the matching HTTP status.

{ "error": { "code": "insufficient_scope",
             "message": "This key does not have the findings:read scope." } }
StatusCodeWhat to do
400invalid_parameterFix the query parameter named in the message
401invalid_keyThe key is missing, wrong, revoked or expired. Check the header, or ask an admin for a new key.
403insufficient_scopeAsk an admin to add the scope or issue a new key
404not_foundCheck the id or path
429rate_limitedWait for the seconds in the Retry-After header, then retry
500server_errorRetry later. If it continues, send the x-request-id to support.

Rate limit: 120 requests per minute per key.

Security

  • Store keys in environment variables or a secrets vault. Never commit them to source control or put them in browser code.
  • Use one key per system so you can revoke one without affecting the rest.
  • Set an expiry date and rotate keys on a schedule.
  • Check the Last Used column on the API Keys page. Revoke any key you do not recognise.
  • Key creation, revocation and use are recorded in Admin > Audit Logs.

Power BI and Excel

In Power BI, choose Get data > Web > Advanced. Enter the URL, for example https://your-polaris-host/api/v1/findings?page_size=200, and add an HTTP request header named x-api-key with your key. Power BI reads the data list as a table. Excel’s Data > From Web works the same way.

Directory sync (Active Directory / Entra ID)

POST /api/v1/users/sync provisions users from a directory export. Unlike the endpoints above it is a write operation and requires the users:sync scope. In production this is called by a scheduled job (or Entra ID provisioning); users are matched by email and their Polaris role is derived from their directory group:

Directory groupPolaris role
AGR-IAA-ADMINSAppAdmin
AGR-IAA-CAEChief Audit Executive
AGR-IAA-AUDITORSMember
AGR-IAA-REGULATORRegulator
AGR-IAA-PREPARERSDelegated Preparer
POST /api/v1/users/sync
x-api-key: YOUR_API_KEY
content-type: application/json

{
  "deactivate_missing": true,
  "users": [
    { "external_id": "ad-object-guid", "first_name": "Thandi",
      "last_name": "Mokoena", "email": "thandi.mokoena@agriseta.co.za",
      "ad_group": "AGR-IAA-CAE" }
  ]
}

Response: {"data":{"created":1,"updated":0,"unchanged":0,"deactivated":0,"warnings":[]}}. With deactivate_missing, accounts previously created by the sync that are absent from the export are disabled — manually created users are never touched. Every change is written to the audit log (query: directory-sync), giving a full provisioning trail. A sample export and sync script ship in scripts/ad-users.sample.json and scripts/sync-ad-users.mjs.
